# Noul

Noul は真偽で答えられる命題に使う。
回答の `noul` は Yes である確率を表す数値であり、根拠文や説明は返さない。

## 使う場面

- 向く: 対象と判定条件を定めた命題に、はい／いいえで答える。
- 向かない: 複数カテゴリから一つを選ぶ分類には使わない。

## 設計の要点

- 質問文に対象と判定条件を含め、単独で読んでも判断できる形にする。
- 必要に応じて true / false の意味を criteria で明示する。
- 根拠や引用が必要なら、Noul が説明まで返す前提にせず、アプリケーション側の要件として設計する。

## 例

- 「問い合わせ本文は、注文代金の返金を明示的に求めているか」
- 「この申請は、記載された締切日より後に提出されたか」
- 「この問い合わせは請求・返品・配送のいずれかに関する内容か」
  複数の担当カテゴリのいずれかに該当するかを確認する質問であり、その後の分類は Choice にする。

`questions` の一要素（キー `asks_refund` は呼び出し側が決める id）:

```json
{
  "asks_refund": {
    "type": "noul",
    "instructions": "問い合わせ本文は、注文代金の返金を明示的に求めているか",
    "criteria": {
      "true": "返金、払い戻し、代金の返還を求める記述がある",
      "false": "返金を求める記述がない。返品や交換のみの依頼を含む"
    }
  }
}
```

`answers` の一要素（`noul` は Yes の確率。値は説明用）:

```json
{
  "asks_refund": { "type": "noul", "noul": 0.97 }
}
```
