# Score

Score は重大度、満足度、経験度など、順序に意味がある尺度上の位置を評価する。
`score` は尺度上の位置を表す。

## 使う場面

- 向く: 順序に意味がある尺度上の位置を評価する。
- 向かない: 単なるカテゴリの一覧には使わない。

## 設計の要点

- レベルを低い側から高い側へ並べ、隣り合う段階の違いが説明からわかるようにする。
- `score` は確率や事象の発生割合を表すものではない。
- `low`、`medium`、`high` のようなラベルだけでは境界がわからないため、各レベルに観察可能な説明を加える。
- TypeSafe のガイドは、まず簡潔な説明を使い、曖昧さが残る場合に対象範囲や実例を含む詳しい説明にする方法を示す。

## 例

質問:
「不具合報告の重大度を、利用者が受ける機能上の影響と回避策の有無に基づいて評価する」

レベル:
- 軽微: 機能への影響がない。
- 中程度: 機能が壊れるが、利用者が使える回避策がある。
- 重大: 機能を利用できず、回避策もない。

`questions` の一要素（`criteria` は低い側から高い側の順の配列。レベル番号は 0 始まりの添字）:

```json
{
  "bug_severity": {
    "type": "score",
    "instructions": "不具合報告の重大度を、利用者が受ける機能上の影響と回避策の有無に基づいて評価する",
    "criteria": [
      "機能への影響がない。",
      "機能が壊れるが、利用者が使える回避策がある。",
      "機能を利用できず、回避策もない。"
    ]
  }
}
```

`answers` の一要素（`score` は各レベル番号に確率を掛けた和で、レベルの間に位置しうる。値は説明用）:

```json
{
  "bug_severity": {
    "type": "score",
    "score": 1.48,
    "confidence": 0.28,
    "legend": {
      "0": "機能への影響がない。",
      "1": "機能が壊れるが、利用者が使える回避策がある。",
      "2": "機能を利用できず、回避策もない。"
    },
    "probabilities": { "0": 0.0, "1": 0.52, "2": 0.48 }
  }
}
```
