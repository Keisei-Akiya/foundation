# ECC → Hermes hooks: 27-registration evidence map

**Scope / method.** ECC's `ecc/hooks/hooks.metadata.json` lists 27 individual registrations (10 PreToolUse, 1 UserPromptSubmit, 1 PreCompact, 2 SessionStart, 2 PostToolUse, 2 PostToolUseFailure, 8 Stop, 1 SessionEnd). This inventory treats metadata entries as the countable registrations; consolidated dispatchers are one registration, with their child checks listed separately below. Evidence combines inspection of the Rust binary (`src/main.rs`), the sample configuration (`hooks.example.yaml`), and the Rust CLI tests (`tests/hooks_cli.rs`, `tests/config_protection_cli.rs`) summarized under “Cross-cutting evidence and caveats” (not live user configuration). “Confirmed” means the stated source contract or the specifically described test behavior was inspected/exercised; it does not imply broader parity. ECC paths are relative to `../ecc`; adapter paths are relative to this directory.

**Purpose-based status criteria (w13b; ECC source pinned at `d2ef2680594f9a17526a6e1a2e18b3d242c5d17b`).** Judge whether Hermes fulfils the full ECC purpose established from the source, not whether it fires at the same event. *Done* = the stated outcome is implemented and supported by relevant tests or live Hermes evidence; this is purpose-level, not a claim of implementation parity. *Partial* = a purpose-relevant outcome exists, but a material purpose, input/state, coverage or delivery condition is missing or unverified. *未達* = no effective purpose-relevant outcome is implemented; a similarly named event or dormant capability is insufficient. Each verdict cites the ECC purpose/source and current Foundation path/evidence; source inspection alone cannot establish Done. Keep consent, policy, platform and safety qualifications explicit. This replaces the inherited event-equivalence criterion and corrects #38/#46's prior contradictory descriptions.

## Cross-cutting evidence and caveats

- **Rust CLI tests.** `mise run test` runs `tests/config_protection_cli.rs` (7 tests) and `tests/hooks_cli.rs` (now 9 tests). They execute the built `foundation` binary with constructed JSON payloads. They cover config-protection block, allow, creation, unrelated-tool, malformed-input, and case-insensitive cases; `preflight` literal `git commit --no-verify`; `hookify` bash block and non-matching allow; lifecycle opt-in/outcome/privacy; and continuous-learning opt-in/privacy. They do not cover `post-observer`, PowerShell preflight, or live Hermes runtime delivery.
- **No Hermes runtime tests.** No Rust test loads Hermes, invokes a Hermes shell-hook callback, or reads `hooks.example.yaml`. Live Hermes callback integration has not been tested.
- **Sample configuration.** Every entry in `hooks.example.yaml` is commented and opt-in; none is installed automatically. Config-protection registers the Rust binary at `pre_tool_call`. `stop_lifecycle` was not connected in the shipped sample and was removed, not ported. Rows that relied on it are No equivalent.
- **Hermes lifecycle events.** `post_tool_call` is registered by the native adapter and dispatches to `post-observer` and `lifecycle`; its delivery has not been tested inside a live Hermes gateway. Other event names (`on_session_start`, `on_session_end`, `on_skill_lifecycle`, `pre_verify`, `post_api_request`) come from inspected Hermes source but remain unconnected. Event contracts, ECC mapping proposals, and the criterion for “No equivalent” are documented in [`docs/hermes-plugin-api.md`](../../../docs/hermes-plugin-api.md); they are source-based, not runtime parity claims.
- **No equivalent disposition.** Retain this status where the Hermes contract lacks a required timing boundary, input/state, or control channel and combining later observer events cannot safely reproduce the ECC behavior. In particular, `post_compaction` cannot replace pre-compaction capture, observer-only session events cannot inject restoration context, and `post_tool_call` does not itself provide MCP health/reconnect state or ECC child-dispatcher controls. Treat event overlap without equivalent policy/state as **Partial**, not parity.
- **Fail-open.** On malformed or unsupported input, every subcommand exits 0 with no block response, so the hook allows the tool call. `hookify` also fails open on malformed or missing rules. This is not a fail-closed policy substitute.
- **ECC source claims.** Registration IDs, events, and descriptions point to `../ecc/hooks/hooks.metadata.json`. Behavioral details are based on the corresponding implementations under `../ecc/hooks/` and `../ecc/hooks/memory-persistence/`. The named subcommands are source evidence only, not demonstrated runtime parity.
- **Pre-commit helper.** Python製のstaged-index fixerは削除済みであり、Rust製ヘルパー `src/bin/precommit.rs`（`mise run precommit`）に置き換えられた。
ヘルパーの自動テストは追加していない。動作は使い捨てリポジトリでの手動実行で確認する。
See `README.md` and `adapters/hermes/hooks/README.md` for current instructions and implementation boundaries.
